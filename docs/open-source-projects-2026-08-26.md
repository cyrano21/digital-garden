# Projets open source à forker / évaluer

Branche de veille créée pour centraliser les projets à récupérer ensuite avec ChatGPT Work.

## Priorité 1

1. **Relaticle** — CRM self-hosted, IA, REST et MCP
   - Dépôt source : https://github.com/Relaticle/relaticle
   - Objectif : forker vers `cyrano21`, puis évaluer un déploiement Coolify et l’usage pour la prospection/CRM.

2. **HTML Anything** — génération locale de pages, présentations, rapports, posters et prototypes via agents IA
   - Dépôt source : https://github.com/nexu-io/html-anything
   - Objectif : forker vers `cyrano21`, puis tester localement avec les CLI/agents déjà disponibles.

## Priorité 2

3. **Eclaire** — workspace IA local-first/self-hosted pour notes, documents, photos, bookmarks et tâches
   - Dépôt source : https://github.com/eclaire-labs/eclaire
   - Objectif : forker vers `cyrano21`, puis évaluer son rôle comme mémoire documentaire privée pour agents.

4. **Memex** — journal IA local-first mobile avec orchestration multi-agent
   - Dépôt source : https://github.com/memex-lab/memex
   - Objectif : forker vers `cyrano21` surtout pour étude de l’architecture.

## Priorité 3 / composants à conserver

5. **Manim Community Edition** — moteur Python d’animations mathématiques/scientifiques
   - Dépôt source : https://github.com/ManimCommunity/manim
   - Objectif : forker vers `cyrano21` pour l’évaluer comme moteur de visualisation pédagogique, notamment pour MimiReady.

6. **dart_agent_core** — framework d’agents stateful, tools, skills, sous-agents et multi-provider LLM
   - Dépôt source : https://github.com/memex-lab/dart_agent_core
   - Objectif : forker vers `cyrano21` et étudier sa réutilisation comme base multi-agent Flutter/Dart.

## Instruction pour ChatGPT Work

Pour chacun des 6 dépôts ci-dessus :

1. Vérifier le dépôt source et sa licence actuelle.
2. Créer un fork dans le compte GitHub `cyrano21` sans modifier le dépôt source.
3. Conserver le nom d’origine du projet, sauf collision avec un dépôt déjà présent dans le compte.
4. Ne pas effectuer de refonte ni de modification fonctionnelle pendant l’étape de fork.
5. Après les forks, produire un récapitulatif avec : dépôt source, fork créé, branche par défaut, licence, dernière activité et éventuels avertissements de sécurité/maintenance.
